# PAZUZU-API v2.0 — API Reference

**Status: specified, not implemented.** `apps/api` is empty (2026-10-09).
No route exists yet. The catalog below is the **planned** `/v2/*` surface.
The live OpenAPI schema will be served at `GET /openapi.json`, generated by
FastAPI at runtime once `apps/api` is built — **this document is not the
schema; `/openapi.json` is.**

## Auth

- Bearer tokens at the Ingestion Gateway; DPoP binding planned (note audit
  #4: DPoP stops replay, not exfiltration — mTLS/payload encryption is a
  gap).
- Every request carries `tenant_id`, `principal`, and `scopes`
  (`ExecutionContext` — contract implemented). Scopes are enforced at the
  gateway **and** re-checked at the service layer.
- `admin` scope required for: `GET /v2/field`, `/v2/replay`,
  `/v2/quarantine/*` mutations, `GET /v2/metrics` (deployment choice).
- Provider credentials are server-side only and never appear in any
  request/response.

## SSE event types (`POST /v2/stream`)

From the `StreamEvent` contract (`packages/contracts/typescript/index.ts`):

| `type` | Meaning |
|---|---|
| `candidate` | A candidate segment was produced (not yet approved) |
| `approved` | Watcher approved; segment emitted |
| `withheld` | S3 gate withheld the segment (fail-closed) — no text follows |
| `revised` | Segment emitted after revision (regeneration / S11 sanitize) |
| `rejected` | Segment rejected; stream may continue or terminate |
| `completed` | Request finished; includes final provenance summary |
| `error` | Terminal error; includes `detail` |

Each event carries `request_id` and optionally `segment_index`, `text`,
`decision` (`approve | revise | reject | quarantine`), and `detail`.

## Versioning

- API major version in the path (`/v2/`). Pipeline behavior is versioned
  separately via `plan_version` + per-station semver — see
  `docs/architecture/pipeline-versioning.md`.
- Breaking API changes bump the path version; pipeline changes do not.
