# PAZUZU-API v2.0 — Deployment

**Status: scheduled.** `infrastructure/` and `migrations/` are empty
(2026-10-09). No Docker Compose file, Dockerfiles, or migration scripts
exist. This document describes the **intended** deployment procedure so the
work can be picked up without reverse-engineering; nothing below has been
executed or verified.

## 1. Bring-up (intended)

```bash
cd ~/workspace/pazuzu-v2
docker compose up --build        # builds api, orchestrator, gateway, telemetry,
                                 # verifier, quarantine, memory, providers images;
                                 # starts postgres + redis
docker compose exec api alembic upgrade head   # planned migrations (none exist yet)
curl -s localhost:8000/v2/health | jq .
```

`docker compose up` is the target one-command bring-up. It does not work
yet because the Compose file and service Dockerfiles have not been written.

## 2. Environment variables (planned — none consumed yet)

| Variable | Used by | Purpose |
|---|---|---|
| `POSTGRES_DSN` | all services | e.g. `postgresql://pazuzu:…@postgres:5432/pazuzu` |
| `REDIS_URL` | gateway, orchestrator | e.g. `redis://redis:6379/0` |
| `PAZUZU_PLAN_VERSION` | orchestrator | Active `ExecutionPlan.version` |
| `PROVIDER_<NAME>_API_KEY` | providers | **Server-side only.** Never logged, never returned. |
| `PROVIDER_<NAME>_BASE_URL` | providers | Upstream endpoint override |
| `PAZUZU_ADMIN_SCOPES` | gateway | Principals granted `admin` scope |
| `PAZUZU_RATE_LIMIT_RPS` | gateway | Per-tenant requests/sec |
| `PAZUZU_S3_DEGRADED_MODE` | orchestrator | `off` (default, fail-closed) or `watermarked` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | all | Telemetry export |
| `LOG_LEVEL` | all | `INFO` default; JSON logs to stdout |

Secrets must come from a secret store (mounted files or env injected by the
orchestrator), never baked into images. Provider keys must never appear in
`StationOutput.data`, telemetry `extra`, or logs — this is a contract-level
guarantee of `ProviderAdapter` ("Upstream credentials never leave the
server").

## 3. Postgres / Redis roles (planned)

**Postgres** (durable, relational):
- `execution_records` — full `StationOutput` sets per request (immutable,
  append-only; keyed by `(request_id, plan_version, station_id,
  station_version)` for retroactive analysis — see
  `architecture/pipeline-versioning.md`).
- `quarantine_records` — `QuarantineRecord` store + review workflow state.
- `memory_records` — S08 `MemoryRecord` store.
- `audit_log` — append-only; hash-chained (each entry commits to the
  previous entry's hash) once the signing control lands.
- `plan_registry` — versioned `ExecutionPlan` documents (append-only).

**Redis** (ephemeral, fast):
- Rate-limit counters (gateway).
- Idempotency keys (`ExecutionContext.idempotency_key`) with TTL.
- Stream-plane fan-out buffers (SSE backpressure).
- Distributed locks for quarantine review checkout (one reviewer at a time).

## 4. Health endpoints (planned — `apps/api` is empty)

| Endpoint | Meaning |
|---|---|
| `GET /v2/health` | Liveness: process up, can serve traffic |
| `GET /v2/ready` | Readiness: Postgres + Redis reachable, provider adapters initialized, plan version loaded |
| `GET /v2/metrics` | Prometheus exposition (request counts, per-station `duration_ms` histograms, `pazuzu_s3_*` gauges) |
| `GET /openapi.json` | Live OpenAPI schema, generated by FastAPI at runtime |

## 5. Log locations (planned)

- All services log **JSON to stdout** (collected by the container runtime);
  no log files inside containers.
- Structured fields on every line: `ts`, `level`, `service`,
  `request_id`, `correlation_id`, `station_id` (where applicable),
  `plan_version`, `station_version`, `msg`.
- **PII redaction applies to logs**: the gateway redacts before dispatch, so
  downstream services never see raw PII — but the redactor itself is
  **scheduled**, so treat all current logs as PII-bearing until it lands.
- Audit-relevant events (quarantine transitions, degraded-mode entries,
  reconciliation overrides, S10 cuts) go to both the JSON log and the
  Postgres `audit_log`.
