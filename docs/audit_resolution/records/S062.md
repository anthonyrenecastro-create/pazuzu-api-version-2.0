# S062 — Live quiver-plot dashboard needs prohibitive t-SNE/UMAP compute

- **Audit ID:** S062 (source issue #62)
- **Title:** Live quiver-plot dashboard needs prohibitive t-SNE/UMAP compute
- **Classification:** [OBS]
- **Severity:** medium
- **Severity rationale:** A dashboard that cannot keep up is worse than no dashboard.

## Original defect description
A live quiver plot on the dashboard for high-dimensional trajectories requires t-SNE/UMAP reduction; computing this live is computationally prohibitive and will lag.

## Affected subsystem
S5 Vector Current / Dashboard

## Root cause
v1.0 promised a live visualization without costing the dimensionality reduction.

## Proposed correction
Replace the live quiver plot with a cheap 2D projection (fixed random projection or the PCA subspace from issue 57) updated at most 1 Hz, in dashboard/trajectory.py; full t-SNE/UMAP remains an offline analysis tool.

## Implementation files
- `dashboard/trajectory.py`
- `stations/s05_vector_current/trajectory.py`

## Verification method
pytest tests/unit/test_dashboard.py::test_trajectory_plot_update_budget

## Test identifier
tests/unit/test_dashboard.py::test_trajectory_plot_update_budget

## Status
scheduled

## Status justification
Dashboard work is scheduled after the trajectory module stabilizes. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Fixed projections can mislead; label the plot as approximate.
