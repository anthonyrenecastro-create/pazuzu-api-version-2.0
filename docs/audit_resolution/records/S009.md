# S009 — No versioning strategy for pipeline logic itself

- **Audit ID:** S009 (source issue #9)
- **Title:** No versioning strategy for pipeline logic itself
- **Classification:** [API]
- **Severity:** medium
- **Severity rationale:** Undistinguishable telemetry from different S5 logics corrupts offline analysis and audit.

## Original defect description
Only the external API is versioned (/v1/); there is no versioning strategy for the pipeline itself. If S5 logic changes, there is no way to distinguish retroactive telemetry produced by the old vs new logic.

## Affected subsystem
Orchestration Pipeline / API

## Root cause
v1.0 versioned the surface but not the behavior behind it.

## Proposed correction
Stamp every envelope and telemetry record with pipeline_version + per-station logic versions (semantic), defined in pipeline/version.py and enforced at startup; /v1/meta exposes the active versions.

## Implementation files
- `pipeline/version.py`
- `pipeline/envelope.py`
- `gateway/routes.py`

## Verification method
pytest tests/unit/test_pipeline.py::test_envelope_carries_logic_versions

## Test identifier
tests/unit/test_pipeline.py::test_envelope_carries_logic_versions

## Status
implemented_unverified

## Status justification
Versioning scheme is designed for v2.0 but not implemented; no test has run. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Retroactive comparisons remain unreliable until the stamp is enforced at ingestion.
