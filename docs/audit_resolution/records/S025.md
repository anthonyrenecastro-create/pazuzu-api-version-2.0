# S025 — Rolling archive summarization is lossy with no KL retention guarantee

- **Audit ID:** S025 (source issue #25)
- **Title:** Rolling archive summarization is lossy with no KL retention guarantee
- **Classification:** [PERF]
- **Severity:** medium
- **Severity rationale:** Unmeasured information loss in the archive undermines the retention claim.

## Original defect description
'Rolling deep archive embedding' — summarization is lossy. There is no computation of KL divergence (or any metric) between original and summary to guarantee 'retention does not fray'.

## Affected subsystem
S2 Sexagesimal Turn

## Root cause
v1.0 asserted retention without a measurable loss criterion.

## Proposed correction
Add a retention-fidelity check in stations/s02_turn/archive.py: score summary vs original with a coverage metric (e.g., QA-probe recall on sampled facts); if fidelity drops below threshold, retain the raw block and flag it.

## Implementation files
- `stations/s02_turn/archive.py`

## Verification method
pytest tests/unit/test_s02.py::test_archive_fidelity_threshold

## Test identifier
tests/unit/test_s02.py::test_archive_fidelity_threshold

## Status
scheduled

## Status justification
Fidelity metric design is pending; the probe methodology needs a labeled fact set. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
QA-probe recall is itself approximate; the guarantee is statistical, not absolute.
