# S040 — Failover to DeepSeek violates p99 SLOs (R1 chain-of-thought too slow)

- **Audit ID:** S040 (source issue #40)
- **Title:** Failover to DeepSeek violates p99 SLOs (R1 chain-of-thought too slow)
- **Classification:** [PERF]
- **Severity:** high
- **Severity rationale:** Failover that breaches the latency SLO is a second outage stacked on the first.

## Original defect description
Grok unavailable -> DeepSeek-V3 assumes both roles. DeepSeek is fundamentally slower (R1 chain-of-thought); failover will violate p99 SLOs.

## Affected subsystem
S3 Dual Ward

## Root cause
The failover plan swapped in a slower model without a latency budget check.

## Proposed correction
Define a degraded-mode contract in config/latency_budget.yaml and stations/s03_dual_ward/failover.py: on failover, switch to a fast non-reasoning configuration (V3 direct, R1 only for flagged segments) and declare degraded SLOs explicitly rather than silently breaching them.

## Implementation files
- `stations/s03_dual_ward/failover.py`
- `config/latency_budget.yaml`

## Verification method
pytest tests/unit/test_s03.py::test_failover_meets_degraded_slo

## Test identifier
tests/unit/test_s03.py::test_failover_meets_degraded_slo

## Status
scheduled

## Status justification
Degraded-mode contract needs measured R1 latencies that do not exist yet; scheduled. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Even the degraded contract may be unachievable on the hardest prompts; needs load testing.
