# S026 — Bridge-attention retrieval inverts the memory-fetch compute order

- **Audit ID:** S026 (source issue #26)
- **Title:** Bridge-attention retrieval inverts the memory-fetch compute order
- **Classification:** [ALG]
- **Severity:** high
- **Severity rationale:** Computing attention over cold memory before fetching stalls the GPU's streaming multiprocessors.

## Original defect description
'Retrieval triggered by bridge-attention salience' requires computing attention weights over cold CPU/pinned memory before fetching to GPU, inverting the standard memory-fetch compute order and stalling SMs.

## Affected subsystem
S2 Sexagesimal Turn

## Root cause
The retrieval trigger was designed without regard for the memory hierarchy.

## Proposed correction
Invert the order in stations/s02_turn/retrieval.py: prefetch candidate blocks to GPU on a coarse salience heuristic first, then compute fine attention over the resident set; cold fetch and compute are pipelined, never sequential.

## Implementation files
- `stations/s02_turn/retrieval.py`
- `stations/s02_turn/attention.py`

## Status justification
Prefetch-first pipeline is designed for v2.0; not implemented or tested. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Coarse prefetch may miss the true salient block; needs a miss-rate metric.
