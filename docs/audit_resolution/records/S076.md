# S076 — Attacker can force the controller into a high-entropy token-exhaustion loop

- **Audit ID:** S076 (source issue #76)
- **Title:** Attacker can force the controller into a high-entropy token-exhaustion loop
- **Classification:** [SEC]
- **Severity:** high
- **Severity rationale:** Adversarial control of sampling parameters is a denial-of-service vector.

## Original defect description
Manipulating temperature based on output entropy allows an attacker to craft prompts that force the controller into a high-entropy loop, exhausting token limits.

## Affected subsystem
S6 Thermodynamic Brake

## Root cause
The controller accepted entropy-increasing feedback with no adversarial bound.

## Proposed correction
Bound the controller's authority in stations/s06_brake/controller.py: hard caps on temperature excursions, a maximum high-entropy dwell time before forced cooldown, and anomaly alerting on adversarial-looking entropy patterns.

## Implementation files
- `stations/s06_brake/controller.py`
- `config/sampling.yaml`

## Residual risk
Bounds that are too tight neuter the controller's legitimate function; tune against real traffic.
