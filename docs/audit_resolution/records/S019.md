# S019 — Routing uncertainty needs all expert hidden states, breaking sparsity

- **Audit ID:** S019 (source issue #19)
- **Title:** Routing uncertainty needs all expert hidden states, breaking sparsity
- **Classification:** [PERF]
- **Severity:** medium
- **Severity rationale:** Synchronous full-expert computation negates the MoE performance claim.

## Original defect description
The routing uncertainty metric requires synchronous computation on all expert hidden states, violating the 'sparse activation' performance claim.

## Affected subsystem
S1 Chimera Gate

## Root cause
The metric was defined on the full expert set instead of the routed subset.

## Proposed correction
Compute uncertainty only over the routed top-k experts in stations/s01_chimera/router.py, plus a cheap proxy (gate entropy over top-k logits) for the unrouted mass; document the approximation in docs/pipeline_semantics.md.

## Implementation files
- `stations/s01_chimera/router.py`

## Verification method
pytest tests/unit/test_s01.py::test_uncertainty_uses_routed_subset_only

## Test identifier
tests/unit/test_s01.py::test_uncertainty_uses_routed_subset_only

## Status
implemented_unverified

## Status justification
Subset-only computation is designed but the router is not yet implemented. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
The proxy may understate uncertainty when the best expert sits outside top-k.
