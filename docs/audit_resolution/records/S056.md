# S056 — /v1/swarm is non-streaming only; no progressive consensus

- **Audit ID:** S056 (source issue #56)
- **Title:** /v1/swarm is non-streaming only; no progressive consensus
- **Classification:** [API]
- **Severity:** low
- **Severity rationale:** Feature gap, not a defect: streaming consensus is a nice-to-have.

## Original defect description
/v1/swarm is non-streaming only; there is no spec for progressive consensus (e.g., streaming medoid updates).

## Affected subsystem
S4 Swarm Agreement / API

## Root cause
v1.0 deferred streaming for the swarm endpoint.

## Proposed correction
Specify server-sent streaming medoid updates in gateway/routes.py (event stream of provisional medoids as branches complete); full result still delivered at completion.

## Implementation files
- `gateway/routes.py`

## Verification method
pytest tests/unit/test_gateway.py::test_swarm_streaming_medoid_updates

## Test identifier
tests/unit/test_gateway.py::test_swarm_streaming_medoid_updates

## Status
scheduled

## Status justification
Streaming consensus is a v2.0 stretch feature; scheduled after the core endpoint. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Provisional medoids may confuse clients that treat them as final; mark them clearly.
