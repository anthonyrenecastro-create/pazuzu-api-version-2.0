# S014 — Sub-query decomposition on high discord risks infinite recursion

- **Audit ID:** S014 (source issue #14)
- **Title:** Sub-query decomposition on high discord risks infinite recursion
- **Classification:** [ALG]
- **Severity:** high
- **Severity rationale:** Unbounded recursion is a liveness failure: the gate can hang instead of answering.

## Original defect description
Decomposing queries into sub-queries on high discord risks infinite recursion if the sub-queries themselves trigger high discord.

## Affected subsystem
S1 Chimera Gate

## Root cause
No depth bound or termination proof was specified for the decomposition loop.

## Proposed correction
Enforce a hard recursion depth cap (default 2) plus a discord-threshold escalation ladder in stations/s01_chimera/decompose.py: depth exceeded -> fall back to best-effort answer with a degradation flag instead of recursing.

## Implementation files
- `stations/s01_chimera/decompose.py`

## Verification method
pytest tests/unit/test_s01.py::test_decomposition_depth_capped

## Test identifier
tests/unit/test_s01.py::test_decomposition_depth_capped

## Status
implemented_unverified

## Status justification
Depth cap is specified in the v2.0 design but not yet implemented or tested. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
A cap that is too shallow may degrade quality on genuinely decomposable queries.
