# S015 — No inference-time fallback if an expert OOMs or crashes

- **Audit ID:** S015 (source issue #15)
- **Title:** No inference-time fallback if an expert OOMs or crashes
- **Classification:** [SEC]
- **Severity:** high
- **Severity rationale:** A single expert failure can take down the whole gate with no recovery path.

## Original defect description
Expert dropout during training is mentioned, but no inference-time expert-fallback is specified if an expert OOMs or crashes.

## Affected subsystem
S1 Chimera Gate

## Root cause
v1.0 only considered training-time robustness, not serving-time fault tolerance.

## Proposed correction
Implement a circuit-breaker + fallback router in stations/s01_chimera/fallback.py: on expert failure, re-route to the next-best expert(s) and mark the response degraded; persistent failures trigger pool rebalancing.

## Implementation files
- `stations/s01_chimera/fallback.py`
- `stations/s01_chimera/router.py`

## Verification method
pytest tests/unit/test_s01.py::test_expert_crash_fallback

## Test identifier
tests/unit/test_s01.py::test_expert_crash_fallback

## Status
implemented_unverified

## Status justification
Fallback design is written for v2.0; neither the module nor its chaos test exists yet. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Fallback re-routing changes output distribution; without monitoring it could mask a systemic expert outage.
