# S034 — No API to pin a macro-block against rotation

- **Audit ID:** S034 (source issue #34)
- **Title:** No API to pin a macro-block against rotation
- **Classification:** [API]
- **Severity:** medium
- **Severity rationale:** System prompts and critical context can be silently summarized away.

## Original defect description
No mechanism exists for the user to 'pin' a macro-block (e.g., the system prompt) to prevent it from being rotated and summarized.

## Affected subsystem
S2 Sexagesimal Turn / API

## Root cause
v1.0 gave the rotation policy no notion of block priority.

## Proposed correction
Add block pinning: POST /v1/context/pin {block_id, ttl} in gateway/routes.py, honored by stations/s02_turn/buffer.py (pinned blocks are excluded from rotation and summarization); pins are listed in GET /v1/context.

## Implementation files
- `gateway/routes.py`
- `stations/s02_turn/buffer.py`

## Verification method
pytest tests/unit/test_s02.py::test_pinned_block_survives_rotation

## Test identifier
tests/unit/test_s02.py::test_pinned_block_survives_rotation

## Status
implemented_unverified

## Status justification
Pinning API is specified; not implemented or tested. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Over-pinning shrinks effective capacity; enforce a pin quota per session.
