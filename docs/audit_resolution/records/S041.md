# S041 — 'Watermarked ward:degraded' is spoofable with a public schema

- **Audit ID:** S041 (source issue #41)
- **Title:** 'Watermarked ward:degraded' is spoofable with a public schema
- **Classification:** [SEC]
- **Severity:** medium
- **Severity rationale:** A spoofable degradation marker lets attackers forge 'degraded' responses.

## Original defect description
'Watermarked ward:degraded' — watermarking is trivially spoofable if the API response schema is public.

## Affected subsystem
S3 Dual Ward / API

## Root cause
v1.0 relied on a plaintext marker as a trust signal.

## Proposed correction
Replace the plaintext watermark with a signed degradation attestation in gateway/attestation.py: HMAC over (response id, degradation reason, timestamp) with a server-side key; clients verify via /v1/verify.

## Implementation files
- `gateway/attestation.py`
- `gateway/routes.py`

## Verification method
pytest tests/unit/test_gateway.py::test_degradation_attestation_signed

## Test identifier
tests/unit/test_gateway.py::test_degradation_attestation_signed

## Status
implemented_unverified

## Status justification
Signed attestation is designed; not implemented or tested. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Key management for the HMAC secret becomes a new operational dependency.
