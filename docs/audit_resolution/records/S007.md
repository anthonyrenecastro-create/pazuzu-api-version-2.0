# S007 — S1-S12 numbering implies mutation while parallel streams imply purity

- **Audit ID:** S007 (source issue #7)
- **Title:** S1-S12 numbering implies mutation while parallel streams imply purity
- **Classification:** [ALG]
- **Severity:** medium
- **Severity rationale:** An ambiguous execution model produces inconsistent implementations across stations.

## Original defect description
S1-S12 numbering implies sequential state mutation, but parallel streams imply functional purity; the architecture vacillates between an imperative pipeline and a dataflow graph.

## Affected subsystem
Orchestration Pipeline

## Root cause
The v1.0 spec never chose an execution model; naming suggests sequence while topology suggests dataflow.

## Proposed correction
Declare the pipeline a dataflow graph in docs/pipeline_semantics.md and pipeline/dag.py: stations are pure functions over immutable envelopes (no in-place token mutation); S1-S12 labels become topological node IDs, and mutation-style APIs are removed.

## Implementation files
- `pipeline/dag.py`
- `pipeline/envelope.py`
- `docs/pipeline_semantics.md`

## Verification method
pytest tests/unit/test_pipeline.py::test_stations_are_pure_functions

## Test identifier
tests/unit/test_pipeline.py::test_stations_are_pure_functions

## Status
implemented_unverified

## Status justification
DAG/envelope design is written for v2.0 but not yet implemented or tested. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Partially migrated stations could mix pure and mutating styles during the transition.
