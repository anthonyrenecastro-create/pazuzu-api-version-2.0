# S012 — Undefined standby pool for 'kept warm' experts; 70B cold start is seconds

- **Audit ID:** S012 (source issue #12)
- **Title:** Undefined standby pool for 'kept warm' experts; 70B cold start is seconds
- **Classification:** [PERF]
- **Severity:** high
- **Severity rationale:** Unplanned expert cold starts translate directly into tail-latency blowouts.

## Original defect description
'Top-2 experts active, others idle (kept warm)' — kept warm on what? A 70B expert's cold start is seconds, not milliseconds, and standby pool sizing is undefined.

## Affected subsystem
S1 Chimera Gate

## Root cause
v1.0 assumed warm standby without specifying the resource that keeps it warm.

## Proposed correction
Define an explicit expert pool manager in stations/s01_chimera/pool.py: keep-warm set sized by routing-frequency forecast, GPU-memory accounting, cold-start budget in config/latency_budget.yaml, and prewarm on deploy.

## Implementation files
- `stations/s01_chimera/pool.py`
- `config/latency_budget.yaml`

## Verification method
pytest tests/unit/test_s01.py::test_pool_cold_start_within_budget

## Test identifier
tests/unit/test_s01.py::test_pool_cold_start_within_budget

## Status
scheduled

## Status justification
Pool sizing requires deployment data that does not exist yet; scheduled after first capacity measurements. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Until sized, the gate will either waste GPU memory or suffer cold-start stalls under burst routing.
