# S036 — Async Watcher emits before it can reject (cannot unsay tokens)

- **Audit ID:** S036 (source issue #36)
- **Title:** Async Watcher emits before it can reject (cannot unsay tokens)
- **Classification:** [PERF]
- **Severity:** high
- **Severity rationale:** Harmful tokens already delivered to the user defeat the purpose of the Ward.

## Original defect description
The Watcher runs async 'one segment behind'. If it rejects segment n-1, segment n is already emitted to the user. A 'kill-switch on stream' only stops future emissions — it cannot unsay past tokens.

## Affected subsystem
S3 Dual Ward

## Root cause
v1.0 pipelined generation and auditing for latency without accounting for the irreversibility of emission.

## Proposed correction
Make the Ward synchronous on high-risk segments in stations/s03_dual_ward/gate.py: risk classifier decides per segment whether to hold emission until Watcher approval (bounded hold, configurable); low-risk segments keep the async pipeline.

## Implementation files
- `stations/s03_dual_ward/gate.py`
- `stations/s03_dual_ward/watcher.py`

## Status justification
Hold-until-approved design is specified for v2.0; not implemented or tested. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Hold decisions depend on the risk classifier; misclassification reintroduces the leak or adds latency.
