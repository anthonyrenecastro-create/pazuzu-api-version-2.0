# S011 — S1 gating is dense softmax, not noisy top-k MoE routing

- **Audit ID:** S011 (source issue #11)
- **Title:** S1 gating is dense softmax, not noisy top-k MoE routing
- **Classification:** [ALG]
- **Severity:** high
- **Severity rationale:** Dense routing defeats the sparsity and load-balancing rationale of the Chimera Gate.

## Original defect description
Gating network G(x) = softmax(Wx) is a dense linear map; real MoE routers use noisy top-k gating to enforce load balancing. The spec describes an outdated routing regime.

## Affected subsystem
S1 Chimera Gate

## Root cause
The v1.0 spec copied a textbook MoE description instead of current routing practice.

## Proposed correction
Implement noisy top-k gating with load-balancing auxiliary loss in stations/s01_chimera/router.py (Switch-Transformer style, k configurable, noise scale annealed during training).

## Implementation files
- `stations/s01_chimera/router.py`
- `stations/s01_chimera/station.py`

## Verification method
pytest tests/unit/test_s01.py::test_noisy_topk

## Test identifier
tests/unit/test_s01.py::test_noisy_topk

## Status
implemented_unverified

## Status justification
Router design is written for v2.0 but the module does not exist and no test has run. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Without the auxiliary loss tuning, routing collapse can still occur even with top-k.
