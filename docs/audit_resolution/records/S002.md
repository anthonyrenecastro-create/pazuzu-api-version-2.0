# S002 — No merge protocol for conflicting parallel-stream directives

- **Audit ID:** S002 (source issue #2)
- **Title:** No merge protocol for conflicting parallel-stream directives
- **Classification:** [ARC]
- **Severity:** high
- **Severity rationale:** Two parallel stations editing the same token with no reconciliation rule yields nondeterministic output.

## Original defect description
The 12-station pipeline mixes critical-path and parallel streams, but never specifies the merge/reconciliation protocol when parallel streams (S4-S5, S7-S10) issue conflicting modification directives for the same token.

## Affected subsystem
Orchestration Pipeline

## Root cause
The v1.0 spec documents station streams without a conflict-resolution layer; merge semantics were left implicit.

## Proposed correction
Add a deterministic conflict-resolution layer in pipeline/merge.py: directives carry (station_id, span, op, priority); conflicts resolved by documented precedence table plus a last-writer-wins tie-break on a monotonic sequence number, all logged to the provenance record.

## Implementation files
- `pipeline/merge.py`
- `pipeline/orchestrator.py`
- `docs/pipeline_semantics.md`

## Verification method

## Status

## Status justification
Merge layer drafted against the v2.0 module layout; no integration test has executed against real station outputs. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Precedence table is a policy choice; mis-ordered precedence could silently suppress a higher-value correction.
