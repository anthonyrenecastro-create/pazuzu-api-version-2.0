# S023 — 60 macro-blocks of 512 tokens caps context at 30,720 tokens

- **Audit ID:** S023 (source issue #23)
- **Title:** 60 macro-blocks of 512 tokens caps context at 30,720 tokens
- **Classification:** [MTH]
- **Severity:** high
- **Severity rationale:** A 30k cap excludes the 128k+ workloads the system is meant to serve.

## Original defect description
A ring of 60 macro-blocks of at most 512 tokens caps context at 30,720 tokens — severely limited for modern RAG and agentic loops requiring 128k+.

## Affected subsystem
S2 Sexagesimal Turn

## Root cause
The base-60 ring was sized for the metaphor, not for workload requirements.

## Proposed correction
Make ring capacity configurable in stations/s02_turn/buffer.py (blocks and block size from config/context.yaml), default to a 256-block ring (~131k tokens), and decouple the count from the sexagesimal naming in docs.

## Implementation files
- `stations/s02_turn/buffer.py`
- `config/context.yaml`

## Verification method

## Test identifier

## Status
implemented_unverified

## Status justification
Configurable capacity is designed but the buffer rewrite is not implemented. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Larger rings increase bridge-attention cost; must be co-tuned with the attention pattern (issue 24).
