# S060 — Embedding every segment on the critical path costs 5-10ms/token

- **Audit ID:** S060 (source issue #60)
- **Title:** Embedding every segment on the critical path costs 5-10ms/token
- **Classification:** [PERF]
- **Severity:** high
- **Severity rationale:** Per-token embedding on the hot path destroys streaming throughput.

## Original defect description
Embedding every emitted segment on the critical path adds ~5-10ms per token (forward pass of the embedding model), destroying streaming throughput.

## Affected subsystem
S5 Vector Current

## Root cause
The trajectory analysis was placed inline with token emission.

## Proposed correction
Move embedding off the critical path in stations/s05_vector_current/station.py: reuse the generator's own hidden states (no separate embedding forward pass) or batch-embed segments asynchronously; S5 operates on a short delay with a bounded staleness guarantee.

## Implementation files
- `stations/s05_vector_current/station.py`

## Verification method
pytest tests/unit/test_s05.py::test_embedding_off_critical_path

## Test identifier
tests/unit/test_s05.py::test_embedding_off_critical_path

## Status
implemented_unverified

## Status justification
Off-path embedding is designed; not implemented or tested. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Reusing generator hidden states couples S5 to the generator's representation; staleness must be bounded and measured.
