# S004 — DPoP prevents replay but not token exfiltration; no mTLS on gateway

- **Audit ID:** S004 (source issue #4)
- **Title:** DPoP prevents replay but not token exfiltration; no mTLS on gateway
- **Classification:** [SEC]
- **Severity:** high
- **Severity rationale:** Exfiltrated bearer/DPoP-bound tokens at the ingress point are a credential-theft path into the pipeline.

## Original defect description
DPoP tokens stop replay but do nothing against token exfiltration, and the Ingestion Gateway specifies neither mTLS nor payload encryption, leaving credential and payload confidentiality unaddressed.

## Affected subsystem
Ingestion Gateway

## Root cause
v1.0 treated DPoP as sufficient transport security, conflating anti-replay with confidentiality.

## Proposed correction
Terminate TLS 1.3 with mandatory mTLS for service callers and DPoP+short-lived tokens for browser clients in gateway/ingestion.py; add request-payload encryption option (gateway/crypto.py) and document the threat model in docs/security_model.md.

## Implementation files
- `gateway/ingestion.py`
- `gateway/crypto.py`
- `gateway/mtls.py`
- `docs/security_model.md`

## Status justification
Gateway security modules are specified for v2.0 but the code and cert-management runbooks do not exist yet; unverified. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Until mTLS ships, the gateway remains exposed to token exfiltration and passive interception.
