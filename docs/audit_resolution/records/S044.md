# S044 — False-reject rate uncomputable without human override labels

- **Audit ID:** S044 (source issue #44)
- **Title:** False-reject rate uncomputable without human override labels
- **Classification:** [OBS]
- **Severity:** medium
- **Severity rationale:** The headline safety metric cannot be measured, so it cannot be managed.

## Original defect description
pazuzu_s3_false_reject_rate cannot be computed without ground-truth human override labels, which are not specified in the telemetry pipeline.

## Affected subsystem
S3 Dual Ward / Telemetry

## Root cause
v1.0 defined the metric without the labeling pipeline that feeds it.

## Proposed correction
Add a human-review sampling loop in pipeline/eval/review.py: sample rejected segments for human adjudication, store labels, and compute false-reject rate from the labeled sample with confidence intervals; export via pipeline/telemetry.py.

## Implementation files
- `pipeline/eval/review.py`
- `pipeline/telemetry.py`
- `docs/telemetry.md`

## Verification method
pytest tests/unit/test_eval.py::test_false_reject_rate_from_labels

## Test identifier
tests/unit/test_eval.py::test_false_reject_rate_from_labels

## Status
scheduled

## Status justification
The review loop needs human-labeling operations that do not exist yet; scheduled. The supplied source references 'eight fatal defects' but does not enumerate which of the 144 issues are fatal; therefore no fatal status is assigned anywhere in this registry.

## Residual risk
Sampling bias in the review set can distort the measured rate; stratify by risk tier.
